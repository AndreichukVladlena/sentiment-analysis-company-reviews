# Решения и результаты

## 1. Задача и критерии готовности

По `Review` требуется вернуть оценку 1–5 и уверенность. Метрика соревнования — MAE. Для тестового задания также нужны EDA, обоснованные дополнительные признаки, Swagger, замена модели и запуск сервиса одной Docker-командой. История в реляционной БД реализована как бонус.

Сервис получает только `Review` и необязательный `Id`. `Rating` существует только в размеченных данных. `Id` нужен для сопоставления строк и истории, в модель он не попадает. Целая оценка — выбор способа прогнозирования; само соревнование допускает дробные значения. Источник условий: [официальное описание Kaggle](https://www.kaggle.com/competitions/sentiment-analysis-company-reviews/overview).

## 2. Данные и разделение

В `train.csv` 60 000 отзывов. После проверки совпадения оценок у повторов удалены 24 лишние копии `Review`. Это исключает дополнительный вес полностью одинакового текста при обучении. Исходный CSV сохранён без изменений.

Для разбиения создаётся отдельная копия текста: `casefold`, схлопывание пробелов, удаление пробелов по краям. Совпадающие копии получают один номер группы. Получились **59 975 групп**: 59 974 одиночных и одна из двух отзывов, отличающихся регистром. Номер группы не является признаком. Модель видит исходный текст, в том числе пунктуацию и прописные буквы.

`StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=2026)` удерживает группу в одной части и старается сохранить доли оценок. В первом фолде 47 980 обучающих и 11 996 проверочных строк. Для коротких опытов раздела 5 baseline дополнительно разделяется только обучающая часть первого фолда.

Словари, IDF и масштабирование числовых признаков обучаются на обучающей части каждого фолда. Замороженный MPNet можно применять до разбиения: его веса не обучаются на этих отзывах. CatBoost и адаптация DeBERTa используют только обучающие строки соответствующего фолда.

EDA обнаружил пересечение текстов между размеченным train и Kaggle test. Строки test не удалялись: файл задаёт полный набор требуемых предсказаний. Разметки test нет, локальную MAE по нему посчитать нельзя. Тестовые тексты не использовались для обучения словарей или подбора параметров.

## 3. Почему медиана

Для постоянного прогноза минимум суммы абсолютных отклонений достигается на медиане обучающих оценок. Здесь это 5; наивная модель не читает текст.

Логистическая регрессия оценивает вероятности пяти классов. Пусть $F(c)=P(Y\leq c\mid x)$. Для целых оценок разность ожидаемых потерь при соседних прогнозах равна

\[
R(c+1)-R(c)=2F(c)-1.
\]

Поэтому выбираем первую оценку, для которой накопленная вероятность не меньше 0,5. Это минимизирует ожидаемую MAE **для распределения, предсказанного моделью**. Само распределение может ошибаться. `confidence` — вероятность выбранного класса; она может быть меньше максимальной вероятности другого класса. Например, для вероятностей `[0.4, 0.2, 0.4]` на оценках `[1, 3, 5]` ответ — 3 с confidence 0,2.

Связь медианы и абсолютной ошибки описана в [документации квантильной регрессии](https://scikit-learn.org/stable/modules/linear_model.html#quantile-regression). Отдельная [калибровка вероятностей](https://scikit-learn.org/stable/modules/calibration.html) не проводилась: confidence не следует интерпретировать как доказанную долю правильных ответов.

## 4. Признаки и эксперименты

Линейная модель со словами и биграммами — разумный ориентир для тональности: полезность таких признаков подтверждалась, например, в [Wang & Manning, 2012](https://aclanthology.org/P12-2018/). Работа поддерживает выбор кандидатов, но не определяет лучшие параметры для этих данных. Их выбирали локальными опытами.

| Блок | Состав | Зачем проверяли |
|---|---|---|
| Слова | TF-IDF униграмм и биграмм | Лексика оценки и короткие сочетания, включая отрицания |
| Символы | `char_wb`, длина 3–5, вес 0,5 | Варианты написания и фрагменты слов |
| EDA, 4 признака | `log1p` длины в символах и словах, наличие `!` и `?` | В EDA эти величины различались между оценками |
| Ещё 9 признаков | `log1p` числа слов из 3+ прописных букв и количества `!` и `?`; 6 индикаторов первого упоминания оценки 0–5 | Сила выражения и явные фразы вроде `one star`, `5/5` |

Числовые признаки стандартизуются по обучающим строкам и умножаются на 0,1. Это отдельные 13 столбцов рядом с TF-IDF. Вес регулирует их масштаб относительно текстовых столбцов и влияние регуляризации. Значения 0,05 / 0,1 / 0,2 сравнивались на внутреннем разбиении; 0,1 оставлен для дальнейших опытов. `Id`, настоящая оценка и номер группы сюда не входят.

**Прямое сравнение наборов**, одинаковые пять фолдов, `C=4`, словный `min_df=5`:

| Набор | MAE |
|---|---:|
| Только слова | 0,19008 |
| Слова + 4 признака EDA | 0,18946 |
| Слова + все 13 числовых признаков | 0,18751 |
| Слова + символы | 0,18869 |
| Слова + символы + 13 числовых признаков | 0,18539 |

Дополнения дают небольшой, измеримый выигрыш; отдельный большой скачок от пунктуации не заявляется. Явное упоминание звёзд доступно из входного текста и не использует скрытый `Rating`; при этом отрицания и контекст могут делать такой сигнал ошибочным.

**Что не вошло:**

- Удаление английских стоп-слов ухудшило MAE внутреннего разбиения с 0,19675 до 0,22614. Сохранение отрицаний внутри удаляемого списка дало 0,21728; более широкий набор исключений — 0,20873. Слова оставлены на основании этих опытов.
- `max_df=0.3` дал 0,19644 на одном внутреннем разбиении. Разница мала; без дальнейшего подтверждения этот вариант не включён.
- Мягкое увеличение веса редких оценок со степенями 0,1 / 0,25 дало 0,18824 / 0,19101 против 0,18676 у соответствующего варианта без весов (`C=8`, `min_df=5`). Балансировка не улучшила основную метрику.
- Стемминг, лемматизация и синтетическая аугментация не проверялись и в решение не добавлены. Символьные признаки уже дали полезный альтернативный сигнал. Утверждать, что аугментация улучшит различение оценок 2–4, без опыта нельзя.

## 5. Подбор параметров и итоговое качество

`min_df` исключает термины, встречающиеся реже заданного числа **обучающих документов**; это не доказательство качества оставшейся фразы. Универсального оптимального порога для другого корпуса нет. Определения параметров: [TfidfVectorizer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html).

После сравнения признаков запущен настоящий `GridSearchCV`: `C ∈ {2, 4, 8}` × словный `min_df ∈ {2, 3, 5}`. Всего 9 сочетаний × 5 фолдов = 45 обучений, затем refit победителя на всех 59 976 строках. Слова ограничены 150 000 признаков, символы — 100 000; эти ограничения памяти не выдаются за подобранные оптимумы. Символьный `min_df=5`, веса 0,5 / 0,1 и набор признаков на этом этапе фиксированы.

Оценщик поиска возвращает **минус MAE медианного прогноза**. Обычный `predict` классификатора и accuracy решали бы другую задачу. Предобработка находится внутри `Pipeline`; `joblib.Memory` переиспользует одинаковые преобразования фолда при разных `C`. На машине с 8 ГБ памяти поиск последовательный, с двумя вычислительными потоками. Основания: [GridSearchCV](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GridSearchCV.html), [кэширование Pipeline](https://scikit-learn.org/stable/modules/compose.html#caching-transformers-avoid-repeated-computation).

**Результат поиска:** выбраны `C=4`, `min_df=5`; средняя MAE **0,18539** против **0,19008** у модели только со словами и **1,43781** у постоянной медианы. Поиск подтвердил прежнюю настройку. Ближайшие сочетания `C=4, min_df=3` и `C=4, min_df=2` дали 0,18557 и 0,18561; небольшой разрыв не означает статистически доказанного превосходства над ними. Полная таблица: [grid_search.csv](../models/grid_search.csv); параметры, ошибки по фолдам, хеш данных и версии библиотек: [training_metrics.json](../models/training_metrics.json). В CSV сохранены названия столбцов scikit-learn `*_test_score`, но значения ошибок переведены в положительную MAE; меньшая величина лучше.

| Сравнение на первом фолде, 11 996 строк | MAE |
|---|---:|
| Медиана обучающих оценок | 1,43781 |
| Слова TF-IDF + Logistic Regression | 0,19348 |
| Итоговый TF-IDF + дополнительные признаки | 0,18881 |
| Замороженный MPNet + CatBoost | 0,44325 |
| Частично дообученная DeBERTa-v3-base | 0,14722 |

Эта таблица использует только один общий фолд; её нельзя напрямую смешивать со средней MAE пяти фолдов. Совпадение данных и разбиений проверяется по SHA-256. DeBERTa дообучалась одну эпоху на всех 47 980 строках обучающей части: два верхних слоя, pooler и классификатор, максимум 128 токенов. MPNet заморожен, ограничен 256 токенами; CatBoost обучен поверх его эмбеддингов. Разные энкодеры и способы обучения не позволяют приписать всю разницу одному фактору. Конфигурации представлены в ноутбуках; исходные модели: [DeBERTa](https://huggingface.co/microsoft/deberta-v3-base), [MPNet](https://huggingface.co/sentence-transformers/all-mpnet-base-v2).

**Ограничение оценки:** эти данные и фолды уже участвовали в выборе признаков и настроек. Приведённые числа служат сравнением при разработке, а не независимой оценкой всей процедуры подбора. Новый случайный split на уже просмотренных данных не исправил бы это автоматически. Такой эффект выбора описан в [примере nested CV scikit-learn](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html). Итоговая сервисная модель дообучена на всём train; отдельного неизвестного теста с разметкой нет.

## 6. Почему в сервисе TF-IDF

Для сервиса выбран компактный TF-IDF, а DeBERTa сохранена как более качественный эксперимент. Для тестового задания это позволяет включить реальные веса непосредственно в Git и запускать CPU-инференс без загрузки сотен мегабайт и зависимости от внешнего хранилища. Обе доступные через `/load_model` модели обучены на всём очищенном train; `word-only` — простой сравнительный вариант.

На Apple M1, два потока CPU, после прогрева: медианная задержка TF-IDF — **1,70 мс**, p95 — **2,06 мс**; DeBERTa — **58,35 / 87,33 мс**, MPNet + CatBoost — **37,17 / 78,76 мс**. Каждый вариант измерен на трёх длинах (52 / 164 / 717 символов), по 10 вызовов. **DeBERTa тоже укладывается в требование по задержке**; отказ от её включения в стандартный образ объясняется доставкой и размером, а не провалом CPU-проверки. Файл TF-IDF занимает 4,48 МБ, словный baseline — 2,60 МБ; локальный каталог DeBERTa — около 740 МБ. Полный подбор и экспорт TF-IDF в этом запуске заняли 54,9 мин.

Измерения разделены: [benchmark.json](../models/benchmark.json) — прямые вызовы моделей на CPU с предобработкой; [http_benchmark.json](../reports/http_benchmark.json) — реальные HTTP-запросы в Docker, включая валидацию и запись SQLite. Прогрев указан отдельно; измерения не являются нагрузочным тестом большого числа клиентов. На другом CPU время изменится. Рекомендация измерять полный путь, а не только матричное умножение классификатора, соответствует [документации производительности scikit-learn](https://scikit-learn.org/stable/computing/computational_performance.html).

Ошибки оценок 2–4 остаются выше ошибок крайних классов. В сравнении полного набора признаков с одними словами (`C=4`, `min_df=5`, раздел 4) MAE для оценок 2 / 3 / 4 снизилась с 1,0516 / 1,2734 / 0,8546 до 1,0135 / 1,2245 / 0,8325. Это улучшение не делает задачу промежуточных оценок решённой. Данные представлены отзывами из конкретного источника; переносимость на другие языки, площадки и время не проверялась.

## 7. Устройство сервиса

Путь запроса: **FastAPI → проверка входа → снимок активной модели → признаки и прогноз → транзакция SQLite → ответ**. Код разделён по ответственности: `api.py`, `model_registry.py`, `history.py`, общий `baseline.py`.

- **Загрузка при старте.** Приложение один раз читает `models/manifest.json`, проверяет контрольную сумму, версию scikit-learn и пробный прогноз. Повреждённый артефакт не заменяется фиктивной моделью.
- **Замена.** `/load_model` принимает идентификатор из доверенного manifest. Кандидат полностью загружается до короткой атомарной замены ссылки. Уже начавшийся запрос заканчивается со старой моделью; все строки его пакета и запись истории используют одну версию.
- **Один процесс.** Реестр активной модели находится в памяти. Поэтому Uvicorn запущен с одним worker; несколько процессов потребовали бы общего механизма согласования. Синхронные обработчики FastAPI выполняют блокирующие операции в пуле потоков ([документация](https://fastapi.tiangolo.com/async/)).
- **Доверенные артефакты.** API не принимает путь, URL или загружаемый pickle. `joblib` может исполнять код при десериализации; SHA-256 защищает от случайной подмены файла, но не от администратора, изменившего и файл, и manifest. Совместимые версии установлены из lock ([правила сохранения моделей sklearn](https://scikit-learn.org/stable/model_persistence.html)).
- **Вход.** Строгие поля исключают преобразование числового Review в строку и булевого Id в число; проверяются Unicode, пустота, длина, размер пакета и тела запроса. Ошибки не повторяют текст отзыва. Подход соответствует [строгому режиму Pydantic](https://docs.pydantic.dev/latest/concepts/strict_mode/).

### История

SQLite выбрана потому, что сервис один и отдельный сервер БД для задания не нужен. Таблицы `requests` и `predictions` связаны `request_id`. Один запрос и все его результаты сохраняются одной транзакцией; ошибка записи возвращает `503`. WAL, короткие соединения и timeout помогают при параллельных запросах, но SQLite по-прежнему имеет одного писателя ([WAL](https://www.sqlite.org/wal.html)).

Хранятся дата, модель, версия и SHA артефакта, Id строки, длина и SHA текста, ответ и время инференса. Текст по умолчанию отсутствует; опция `STORE_REVIEW_TEXT=1` сохраняет его явно. Хеш — средство сопоставления, не обещание анонимности. Публичного эндпоинта чтения истории нет. Файл `/app/data/history.sqlite3` лежит в именованном Docker volume и переживает перезапуск и `docker compose down`; `down -v` удаляет историю.

Пример просмотра последних записей:

```bash
docker compose exec api python -c 'import sqlite3; c=sqlite3.connect("/app/data/history.sqlite3"); print(c.execute("SELECT request_id, model_id, item_count FROM requests ORDER BY created_at DESC LIMIT 5").fetchall())'
```

### Контейнер

Двухэтапная сборка отделяет установщик зависимостей от runtime. Версии Python и uv закреплены digest, зависимости — `uv.lock`. В образ не попадают данные, кэши, ноутбуки, PyTorch и инструменты разработки. Сервис работает от UID 10001, корневая файловая система доступна только для чтения; запись разрешена в volume истории и `/tmp`. Порт опубликован только на localhost. Источники решений: [Docker best practices](https://docs.docker.com/build/building/best-practices/), [uv в Docker](https://docs.astral.sh/uv/guides/integration/docker/).

Это локальный сервис для проверки задания. Аутентификация, HTTPS, распределённая история и несколько реплик в объём реализации не входят. Выбор активной модели сбрасывается на `tfidf` после рестарта; история сохраняется независимо от него.

## 8. Проверки и воспроизведение

На финальной версии выполнены **41 тест**, Ruff, проверка форматирования, `uv lock --check`, проверка схемы всех ноутбуков и отсутствия сохранённых ошибок. SHA исходников совпадают с метаданными обучения; SHA и размеры обоих артефактов — с manifest. Итоговая модель сходится за 184 итерации при лимите 250, словный baseline — за 136.

Отдельно создан чистый локальный клон коммита `4058c92`, без `data/raw`, `data/cache` и `.venv`. Команда `docker compose up --build -d --wait` подняла готовый сервис. Подтверждены Swagger, одиночные и пакетные запросы, ошибки валидации, обе модели и сохранение предыдущей модели после неудачного выбора. Контейнер: Linux arm64, UID 10001, корневая файловая система только для чтения; размер образа по Docker — 157 МБ.

Пакет из двух прогнозов модели `word-only` найден в SQLite по точному `X-Request-Id` до и после рестарта, с прежними ответами и версией модели. Текст отзыва не записан. Активная модель после рестарта — `tfidf`, как задано в manifest. Одиночный запрос максимальной разрешённой длины 20 000 символов обработан за 47,2 мс.

HTTP benchmark на Apple M1, Colima 2 vCPU / 2 ГБ: по 30 запросов для текстов 77 / 396 / 1297 символов после трёх прогревочных; p95 — 8,63 / 7,94 / 10,40 мс. Для 30 пакетов по 16 отзывов p95 — 22,15 мс. Это время включает HTTP и синхронную запись SQLite. Доказательства: [verification.json](../reports/verification.json), [http_benchmark.json](../reports/http_benchmark.json).

EDA выполнен заново из чистого ядра. В baseline выполнены новый поиск через CLI и разделы GridSearch/экспорта из свежего ядра с загрузкой завершённого поиска. Прежние опыты сохранены, их числа сверены; полный повтор всех старых опытов в эту сессию не выполнялся. Форматирование MPNet/DeBERTa проверено по AST, без изменения вычислений; их сохранённые метрики перепроверены по кэшам, а CPU-задержки измерены заново.

Проверка Docker проведена на arm64. Workflow для GitHub Actions на Ubuntu подготовлен, удалённый запуск не выполнялся. В тестах есть предупреждение Starlette о будущем переходе с `httpx` на `httpx2`; с закреплёнными версиями все проверки проходят.

Тесты покрывают предобработку без утечки, медианное декодирование, сохранение модели, контракт API, ограничения ввода, повреждённый файл, замену модели во время запроса, согласованность истории и откат транзакции. HTTP smoke выполняется отдельно от TestClient. CI повторяет тесты и Docker smoke, но его удалённый запуск требует публикации коммитов.

Для локального повторения экспериментов нужны исходные CSV из соревнования. Для запуска сервиса они не нужны. Команды приведены в README. Кэш поиска TF-IDF привязан к данным, исходникам, версиям библиотек и параметрам. Кэши трансформеров проверяют данные, разбиение и конфигурацию, но не полный исходный код ноутбука; при изменении алгоритма их следует пересоздать. Произвольные чужие joblib-файлы не следует подставлять в кэш или manifest.

Исторические запуски на Apple M1 с 8 ГБ: кодирование MPNet заняло 17,8 мин, CatBoost — 0,5 мин; частичное обучение DeBERTa — 67,9 мин, прогноз валидации — 13,7 мин. Эти времена относятся к настройкам и устройству соответствующих ноутбуков, не к CPU HTTP-инференсу.

## 9. Использование агентов

OpenAI Codex участвовал в исследовании, программировании, документации и запуске экспериментов. Работа была разделена на ML, API и независимое ревью; интеграция и запуск Docker проверялись отдельно. Агентские проверки дополнялись тестами и фактическими вычислениями. Это указание оставлено в репозитории согласно условию задания.
