# Решения и результаты

## 1. Данные и проверка качества

Задача — предсказать оценку компании от 1 до 5 по тексту отзыва. Метрика соревнования — MAE. `Id` не используется как признак. В Kaggle `test.csv` нет известных оценок, поэтому качество проверяем на размеченном `train.csv`.

Из 60 000 строк удалены 24 повтора с одинаковыми `Review` и `Rating`. Осталось 59 976 отзывов. Ещё одна пара различается только регистром или пробелами. Для разбиения используем копию текста с единым регистром и схлопнутыми пробелами: совпавшие копии должны попадать в одну часть. Всего 59 975 таких групп; 59 974 содержат один отзыв, одна — два. Модель получает исходные тексты.

Разбиение: `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=2026)`. На первом фолде 47 980 обучающих и 11 996 проверочных отзывов. Словари и масштабирование обучаются только на обучающей части каждого фолда. Пересекающиеся с train строки Kaggle test не удаляются.

Эти фолды использовались и для выбора признаков и параметров. Поэтому приведённая MAE описывает проведённый подбор; независимого итогового теста нет.

## 2. Почему прогнозируем медиану

Для постоянного целочисленного ответа `c` переход к `c + 1` увеличивает абсолютную ошибку на 1 для каждой оценки не выше `c` и уменьшает её на 1 для каждой оценки выше `c`.

Изменение суммы ошибок равно **числу оценок слева минус число оценок справа**. Пока больше половины оценок справа, ответ выгодно увеличивать; когда больше половины слева — уменьшать. Минимум достигается в медиане, по обе стороны от которой не больше половины наблюдений. При равных половинах оптимальных ответов может быть несколько.

Наивная модель всегда отвечает медианой обучающих оценок — здесь это 5. Логистическая регрессия выдаёт вероятности оценок 1–5 для конкретного отзыва. Выбираем первую оценку, на которой накопленная вероятность достигает 0,5. Это тот же аргумент, применённый к вероятностям: ответ минимизирует ожидаемую абсолютную ошибку для предсказанного распределения.

`confidence` в API — вероятность возвращённой оценки. Она может отличаться от максимальной вероятности; отдельной калибровки уверенности не проводилось.

## 3. Признаки

| Блок | Что извлекаем | Причина проверить |
| --- | --- | --- |
| Слова и биграммы | `service`, `not good` | Лексика оценки и короткий контекст, включая отрицания |
| Символьные фрагменты | Части слов длиной 3–5 символов, `char_wb` | Общие части разных написаний слов |
| Четыре признака EDA | `log1p` длины в символах и словах, наличие `!` и `?` | В EDA эти признаки различались между оценками |
| Девять дополнительных | `log1p` количества заглавных слов и знаков `!`/`?`; шесть флагов упоминания оценки 0–5 | Эмоциональная форма записи и явные фразы `one star`, `5/5` |

Числовые столбцы масштабируем по обучающим данным и умножаем на 0,1. Вес ограничивает их влияние относительно TF-IDF. Он выбран среди 0,05 / 0,1 / 0,2 на внутреннем разбиении совместно с `C` 1 / 2 / 4 / 8. Лучшее сочетание того опыта: C=8, вес 0,1, MAE 0,19185. Окончательное C выбиралось позднее на пяти фолдах.

TF-IDF по словам содержит униграммы и биграммы, использует `sublinear_tf=True` и не более 150 000 признаков суммарно. Символьный словарь — не более 100 000 фрагментов, `min_df=5`, вес 0,5. Пределы словарей ограничивают память; они не выдаются за найденные оптимумы.

Прямое сравнение на одинаковых пяти фолдах, C=4 и словный min_df=5:

| Признаки | Средняя MAE |
| --- | ---: |
| Только слова и биграммы | 0,19008 |
| Слова + четыре признака EDA | 0,18946 |
| Слова + все 13 числовых признаков | 0,18751 |
| Слова + символьные фрагменты | 0,18869 |
| **TF-IDF по словам и символам + 13 числовых признаков + Logistic Regression** | **0,18539** |

Оставлен полный набор. Выигрыш относительно словного baseline небольшой — около 2,5%.

### Что проверили и отклонили

На одном внутреннем разбиении:

| Обработка слов | MAE |
| --- | ---: |
| Сохранить все слова | 0,19675 |
| Удалить стандартные английские стоп-слова | 0,22614 |
| При удалении сохранить отрицания | 0,21728 |
| Сохранить также связки и слова контекста | 0,20873 |
| Удалить термины из более чем 30% отзывов | 0,19644 |

Стоп-слова оставлены. Последний вариант дал слишком небольшое преимущество на одном разбиении, чтобы менять итоговую настройку без подтверждения.

В прежних пятифолдовых опытах мягкие веса редких классов со степенями 0,1 / 0,25 дали MAE 0,18824 / 0,19101 против 0,18676 без весов при C=8, min_df=5 и полном наборе. Доля каждого класса считалась только по обучающим строкам фолда. Веса не вошли в итоговую модель. Код этих отклонённых опытов удалён из основного пути чтения; результаты сохранены здесь и в истории Git.

Стемминг, лемматизация и синтетическая аугментация не проверялись. Утверждать их пользу по этим экспериментам нельзя.

## 4. GridSearchCV и итоговый baseline

Для полного набора признаков проверены **все 9 сочетаний C ∈ {2, 4, 8} и словного min_df ∈ {2, 3, 5} на пяти фолдах**. После 45 обучений выбранный вариант обучен на всех 59 976 отзывах.

`min_df` — минимальное число обучающих отзывов, содержащих признак. Значения 2 / 3 / 5 заданы вручную для проверки редкой лексики. Ранее порог 10 проверялся без символьных признаков: MAE 0,19008 против 0,18793 у порога 5 при C=8. Это послужило основанием сузить сетку, но не доказывает, что 10 хуже с полным набором.

Для каждого сочетания считаем MAE на проверочных фолдах. Функция `negative_median_mae` передаёт ошибку со знаком минус: `GridSearchCV` максимизирует переданную метрику, поэтому выбирает наименьшую ошибку. В результатах показывается положительная MAE.

| C | min_df | Средняя MAE |
| --- | --- | ---: |
| **4** | **5** | **0,18539** |
| 4 | 3 | 0,18557 |
| 4 | 2 | 0,18561 |
| 8 | 2 | 0,18579 |
| 8 | 3 | 0,18614 |
| 8 | 5 | 0,18676 |
| 2 | 5 | 0,18686 |
| 2 | 2 | 0,18709 |
| 2 | 3 | 0,18734 |

Ближайшие результаты очень близки. C=4, min_df=5 — лучший проверенный вариант; статистически доказанного превосходства над соседними значениями не заявляется.

Постоянная медиана даёт 1,43781 MAE. По оценкам 2 / 3 / 4 полная модель всё ещё ошибается в среднем на 1,0135 / 1,2245 / 0,8325 балла. Редкие промежуточные оценки — главное слабое место baseline.

## 5. DeBERTa

Все строки таблицы оценены на **одном и том же первом фолде**:

| Модель | MAE |
| --- | ---: |
| TF-IDF по словам и символам + 13 числовых признаков + Logistic Regression | 0,18881 |
| Частично дообученная DeBERTa-v3-base | **0,14722** |

У DeBERTa обучены два верхних слоя энкодера, pooler и классификатор: одна эпоха, максимум 128 токенов. На выборке 5 000 отзывов около 13,7% оказались длиннее этого предела. После первого опыта настройки зафиксированы: batch size 8, encoder LR 3e-5, head LR 1e-4, AdamW (`foreach=False`), прогрев 5%, ограничение нормы градиента 1, seed 2026. Используется медленный токенизатор и ревизия `8ccc9b6f36199bec6961081d44eb72fb3f7353f3`.

### Финальная модель и инференс

Отдельный checkpoint `deberta_v3_base_full_33305736a2d2` обучен на всех 59 976 строках. Его `training_scope="full"`, конфигурация и состав файлов проверены; SHA256 весов — `28e21afd362a6fe6ca3cca7d5a80e705e2d30c7168802c6f72ee66b30c9315d9`, отличный от всех фолдовых весов. По журналам M4 обучение фолдов 2–5 заняло 9,6 / 9,3 / 13,8 / 12,7 минуты, финальное обучение — 16,4 минуты, весь запуск с подготовкой и проверкой — около 75,9 минуты. Окружение: Python 3.12.13, PyTorch 2.14.1, Transformers 4.57.6, scikit-learn 1.9.1, MPS. Первый фолд обучен на M1; остальные и full — на M4. Побитовая воспроизводимость между устройствами не заявляется.

По умолчанию API использует компактный TF-IDF. Его файл занимает около 4,48 МБ, словный baseline — 2,60 МБ; каталог DeBERTa — около 740 МБ. Две версии TF-IDF включены в Git и обеспечивают запуск после клонирования. Для DeBERTa предусмотрен экспорт финального каталога и сборка с дополнительными зависимостями. Веса загружаются локально, без сетевых обращений во время инференса.

6 октября финальная модель экспортирована штатной командой `company_reviews.export_deberta` и проверена на 15 отзывах: коротком, среднем и длинном для каждой истинной оценки. Это smoke-проверка инференса на обучающих для full-model примерах, а не новая оценка качества. Сравнены фиксированное дополнение до 128 токенов, динамическое дополнение батча и одиночные вызовы; вероятности совпали в пределах `atol=1e-5, rtol=1e-4`, медианные ответы — точно. Проверены диапазон 1–5 и `confidence` именно выбранной оценки.

На CPU Apple M1, два потока, 15 одиночных вызовов после двух прогревочных дали медианное время **113 мс**, p95 **175 мс**. Время включает токенизацию и прогноз, без HTTP и загрузки весов. Загрузка через API с проверкой файлов заняла 7,36 с; батч из 15 отзывов через TestClient — 1,17 с. TestClient подтвердил переключение TF-IDF → DeBERTa → TF-IDF, совпадение baseline до/после и 18 записанных прогнозов в SQLite с правильным отпечатком модели и без исходного текста.

Тот же **full-checkpoint встроен в Docker-образ** и проверен через HTTP в Linux arm64: Colima, 2 CPU, 2 ГБ памяти, PyTorch 2.14.1+cpu. Все 15 ответов совпали с macOS; максимальная разница вероятности выбранной оценки — 0,00000179. После пакетного прогрева медианное время одиночного запроса — **0,217 с**, p95 — **0,432 с**, максимум — **0,598 с**, включая HTTP и SQLite. Переключение с загрузкой DeBERTa заняло 6,80 с и не входит в задержку прогретого `/predict`. Это небольшой замер на конкретном оборудовании, без параллельной нагрузки.

## 6. Сервис и воспроизведение

FastAPI предоставляет `/predict`, `/load_model`, `/models`, `/health` и Swagger. Запрос может содержать один отзыв или массив. SQLite сохраняет историю успешных запросов; по умолчанию без исходных текстов.

`models/manifest.json` задаёт меню доверенных локальных моделей. Сервис проверяет контрольные суммы и пробный прогноз перед переключением; если загрузка не удалась, сохраняет прежнюю модель. Весь пакет отзывов обрабатывается одной выбранной моделью. `confidence` всегда относится к возвращённой оценке.

Команда `python -m company_reviews.export_deberta <каталог>` переносит финальную модель и токенизатор в `models/deberta/`, рассчитывает контрольные суммы и добавляет запись в каталог. Она принимает только результат обучения на всех данных с длиной 128 токенов и исходным медленным токенизатором. Повторное сохранение baseline сохраняет регистрацию DeBERTa. Каталог читается при старте: после экспорта сервис нужно пересобрать и перезапустить, затем выбрать `deberta` через `/load_model`.

Стандартный Docker включает зависимости API и две обученные версии TF-IDF. После клонирования достаточно команды из README. Сборка с `MODEL_EXTRA=deberta` дополнительно устанавливает CPU-версию PyTorch для Linux, Transformers и SentencePiece. Для повторного обучения нужны данные Kaggle; они не включены в Git.

6 октября 2026 года все 35 ячеек кода baseline выполнены последовательно на данных соревнования за 81 минуту. Подтвердились все таблицы текущих опытов: MAE 1,43781 для медианы, 0,19008 для словного варианта и 0,18539 для итоговой модели; GridSearchCV вновь выбрал C=4, min_df=5. Модели заново обучены на всех очищенных данных, сохранены и загружены для проверки прогноза.

Финальная проверка сервиса: **65 тестов прошли**, Ruff и `git diff --check` — без ошибок. Ноутбук DeBERTa прошёл проверку схемы nbformat: десять выполненных ячеек, без error outputs; код ячеек сохранён. Из чистого снимка Git `5e47aaa` стандартная поставка поднялась одной командой Compose с пустым отдельным томом истории. Проверены одиночный и пакетный прогнозы, смена двух TF-IDF-моделей, Swagger и сохранение истории после рестарта. Отдельно полный Docker-образ с финальной DeBERTa прошёл проверки выше; его 32 прогноза также сохранились после рестарта. Проверочные контейнеры и только их временные тома удалены, основной том истории сохранён.

## Источники решений

- [Wang & Manning, 2012](https://aclanthology.org/P12-2018/) — линейные текстовые модели как сильный ориентир для тональности.
- [TfidfVectorizer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html) — определения признаков, частотных порогов и предела словаря.
- [GridSearchCV](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GridSearchCV.html) и [Pipeline](https://scikit-learn.org/stable/modules/generated/sklearn.pipeline.Pipeline.html) — подбор параметров с предобработкой внутри фолдов.
- Карточка [DeBERTa-v3-base](https://huggingface.co/microsoft/deberta-v3-base) — назначение и устройство исходной модели.
- [Transformers: сохранение и загрузка модели](https://huggingface.co/docs/transformers/v4.57.1/en/main_classes/model) — локальный каталог весов и конфигурации; токенизатор сохраняется вместе с моделью.
- [uv и PyTorch](https://docs.astral.sh/uv/guides/integration/pytorch/) — отдельный CPU-индекс для Linux, обычная сборка с MPS для macOS.

Источники помогли выбрать кандидатов. Конкретные параметры и приведённые метрики основаны на локальных экспериментах.
